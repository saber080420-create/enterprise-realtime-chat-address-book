# 个人文档入库与问答

## 当前范围

AI 助手新增「个人文档问答」：上传 UTF-8 `.txt` / `.md`、列表、原文查看、移出知识库、关键词检索和流式带引用回答。上传只写入本机 MySQL，不调用模型；提问时问题与选中的片段会发送给 DeepSeek。

- 单篇最多 80000 字节、正文最多 20000 个 Java 字符；每账号最多 50 篇有效文档。
- 严格 UTF-8 解码；处理 BOM 和 CRLF；拒绝空文件、异常编码、控制字符、非法文件名和超长正文，不静默截断。
- 文件名只是标题，不用于构造磁盘路径；正文保存在独立表，不进入公开 uploads 静态目录。
- Markdown/HTML 均按纯文本呈现，不执行标签、脚本或外链。纯文本分片和关键词提取保留代码文字，不套用公告 HTML 清洗。
- 默认只对上传者可见，管理员也不能通过 AI 文档接口读取别人的个人文档。账号状态和角色从当前 MySQL 校验，不能由客户端指定 ownerId。
- 上传事务先锁定用户行，再检查有效文档数量并插入，防止并发突破配额。
- 移出是软删除：正文仍保留在数据库中，页面没有恢复入口；新检索和原文接口立即排除。已生成的回答和已经展示的片段不会自动擦除，也不能撤回已发送给模型的内容。物理清理/保留期尚未实现。
- 关键词检索按 600 字符切分、100 字符重叠，最多 4 篇各取一个片段；提供片段前复查所有权、有效状态和正文。无匹配时不调用模型。
- SSE `sourceType=document` 区分文档和公告；目前 ID 字段沿用 `announcementId` 以兼容旧引用协议，由 sourceType 决定来源接口，不把不同资源的 ID 混用。

关键词基线已完成少量浏览器联调；文档向量版已实现并通过自动化及真实向量服务测试，页面验收待重启后端。尚未实现 PDF/Word/OCR、共享文档权限、编辑/版本管理、批量导入、文档物理清理。

## 文档向量检索

- 页面新增「文档·语义检索」，上传与关键词模式共用个人文档库；上传后手动点击「同步个人文档索引」。新增文档需要再次同步，切换模式不会自动调用 embedding。
- 复用本机 Ollama / bge-m3、1024 维和 PGVector，但使用独立 `document_embedding` 表，避免公告和文档同编号串库。索引版本在 `AI_INDEX_VERSION` 基础上附加 `:document-plain-v1`，区别纯文本分片方式。
- 单实例文档同步最多一个任务，最多 50 篇；分批 8 个片段，工作预算 5 分钟，在批次之间检查。与公告同步是两个独立工作队列，可能同时使用 Ollama，尚未实现统一资源调度。进度只有任务发起者可见，显示处理、复用和因变更/移出而跳过的数量。
- 指纹包含文档 ID、所有者、标题、content_hash 和实际正文。未变索引复用；重新生成完成后复查 MySQL，有效且未变才事务替换。失败保留旧行，重试复用已完成部分。
- 查询先从 MySQL 取得自己的有效文档，检查当前指纹和完整分片数；只把授权且版本匹配的候选交给参数化 SQL 做精确余弦排序。命中后再检查当前 MySQL 所有权和正文，重建片段，最多 4 篇。
- 无有效文档时直接无匹配；存在文档但没有有效索引时明确提示同步，不偷偷回退关键词。部分未索引时只搜有效部分并显示检索范围受限。低于 `AI_RAG_MIN_SCORE`（默认 0.45）的片段不交给 DeepSeek；该值不是准确率，待固定评测集校准。
- 移出后的向量可能仍保留，但不能匹配当前有效候选，不能进入新回答；后台物理清理尚未实现。原文接口继续按当前 MySQL 权限校验。同步/查询最后复查后仍存在极短的并发变化窗口，不宣称跨库强事务一致性。

### 启用与迁移

本机知识数据库已追加 `document_embedding` 表，没有修改 MySQL 业务记录或原公告向量。其他已有环境需重新执行 `big-event/src/main/resources/db/vector/schema.sql`（仅创建缺失表）；不能删除 Docker 数据卷来升级。

沿用 `AI_RAG_ENABLED=true`、Ollama/BGE-M3、PGVector 的已有设置，不新增付费模型或配置项。重启后端再刷新，文档语义入口才会启用；旧后端只显示禁用入口和升级提示。

验收顺序：上传合成资料 → 同步 → 再次同步观察复用 → 换措辞提问 → 检查引用 → 无关问题 → 移出后重问及检查旧引用。关键词模式保留，用于对照召回差异。

## 数据库与启动

本机 `big_event.ai_document` 已在 2026-09-08 创建并核对（InnoDB / utf8mb4，初始 0 条）。没有修改现有业务表或记录。

其他环境需在业务 MySQL 数据库中执行 `big-event/src/main/resources/db/knowledge/schema.sql`。该脚本仅 `CREATE TABLE IF NOT EXISTS`；现有 Docker 数据卷不会自动补跑初始化脚本，不能为加表删除数据卷。新数据卷初始化已在 Compose 中挂载此脚本。

在原来已设置 DeepSeek Key 的后端 PowerShell 中停止旧进程，再于 `big-event` 目录运行：

```powershell
mvn spring-boot:run
```

保留已有环境变量；不需要重新把密钥粘贴到聊天中。前端刷新，确认「个人文档问答」可选。后端旧版本时该入口禁用。

## 验收示例

使用仓库 `docs/fixtures/knowledge-demo.txt`（纯合成演示，不是企业真实制度）：

1. 上传，列表出现标题，原文保持文本格式。
2. 提问「演示差旅报销需要几天内提交？」应找到“三个工作日”及引用，点击引用查看原文。
3. 提问「演示差旅报销的金额上限是多少？」检索虽命中，但资料没写金额，模型应明确依据不足。
4. 使用无关随机词，应无匹配且 Token 为 0。
5. 移出后重新提问，不能再引用该文档；旧引用点击应提示来源不可用。
6. 用另一个账号验证列表、按 ID 查看和移出均不能访问此文档。
