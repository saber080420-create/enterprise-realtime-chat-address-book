# 公告语义检索：BGE-M3 + PGVector

## 启动

```powershell
docker compose --profile rag up -d pgvector ollama
docker compose exec -T ollama ollama pull bge-m3
```

在原来设置 DeepSeek Key 的后端终端中停止服务，再执行：

```powershell
$env:AI_RAG_ENABLED='true'
mvn spring-boot:run
```

刷新 AI 助手，选「公告·语义检索」，点击「同步可见公告索引」，等同步完成后提问。
未开启此开关时，不连接向量服务，普通聊天和关键词检索继续可用。服务故障不自动切换检索方式，页面会明确报错。

PGVector 在本机 5433，Ollama 在 11434；两者仅绑定 127.0.0.1。原 MySQL/Redis 不迁移。
Compose 命名卷保存数据库与模型，正常重启不丢失。不要执行 `docker compose down -v`，它会删除项目数据卷。
Postgres 表初始化脚本仅在空数据卷首次启动时执行。已有卷若缺表，需对本项目知识库执行 `big-event/src/main/resources/db/vector/schema.sql`。

## 数据路径与权限

1. MySQL 按当前用户状态、角色和部门过滤最新 200 篇已发布公告，最多读取每篇前 20000 字符。
2. 本地去 HTML、600 字符切分/100 字符重叠，标题随片段一起传给本机 Ollama `/api/embed`。
3. 返回必须是 1024 维非零有限数向量；批次最多 8 条，禁止静默截断输入。
4. PostgreSQL 保存公告 ID、模型/索引版本、SHA-256 内容与权限指纹、分片编号和 vector(1024)，不重复保存正文。
5. 语义查询先从 MySQL 获得授权 ID 和当前指纹，批量检查索引覆盖率，再在 PGVector SQL 中过滤这些候选后做精确余弦排序。
6. 选取最多 4 篇，回查 MySQL 权限/版本并从当前正文重建片段，才发送给 DeepSeek。查询原文同样重新鉴权。

公告和问题的向量化只在本机执行；被检索选中的正文片段仍会发送给 DeepSeek 用于生成回答。

## 同步、故障与限制

- 「同步可见公告」为当前用户发起的异步任务，单实例同时只运行一项；最多处理当前可见 200 篇。查询任务状态只能看到自己最近的任务。
- 不变的文档复用索引；变更后先生成完整向量，再事务替换该文档对应模型版本的行。单文档失败保留原索引，可重试。
- 公告修改/撤回、用户调部门不等待同步即可阻止旧资料被检索，依赖查询时 MySQL 指纹和 ACL；新的有效内容需要再次同步才可召回。
- 不自动物理删除已撤回/已删除公告的遗留向量；它们不匹配当前授权候选，不能用于回答。后台清理与自动增量同步留待后续。
- 同步工作预算 5 分钟（在批次之间检查），单次 embedding 连接超时 5 秒、读取超时 60 秒。状态显示部分进度；失败可再次同步并复用完成部分。
- 默认最低余弦相似度 0.45 是待评测参数，不是准确率或概率；用 `AI_RAG_MIN_SCORE` 调整。未建立有效索引会提示先同步；部分索引缺失/过期时页面显示范围受限。
- 本版只做 dense embedding，没有启用 BGE-M3 的 sparse/multi-vector 功能。没有 HNSW；小规模使用精确余弦检索便于验证权限过滤和基线召回。
- `AI_INDEX_VERSION` 用来隔离模型/切分版本。更换同名模型权重或切分算法时也必须更新版本并重建；不要把两个不同模型的向量混用。
- 仍使用独立模型适配层，未完成 Spring AI/Boot 升级；当前公告向量功能不依赖该升级。

## 测试

常规测试不需要向量服务：

```powershell
mvn '-Dtest=org.itheima.ai.*Test' test
```

真实集成测试（在 big-event 目录）：

```powershell
mvn '-Dtest=VectorIntegrationTest' '-Dvector.integration=true' '-Dembedding.integration=true' test
```

真实测试只使用合成请假/停车场资料，不调用 DeepSeek。它在知识数据库里创建随机命名的测试 schema，结束时只删除自己创建的 schema；不改应用索引和 MySQL 数据。
省略 `-Dembedding.integration=true` 时仅验证真实 PostgreSQL，使用确定性的测试向量，不算真实模型效果测试。
Compose 已固定本次下载的镜像 digest，避免浮动 tag 导致复现环境变化。

## 技术要点

- 向量检索解决不同措辞的相近语义召回；它不能代替权限检查，也不保证答案正确。
- PGVector 是索引副本，MySQL 是权威业务数据。双库暂时不一致时，用版本指纹避免过期召回。
- SQL 参数化传入授权候选与向量，不能让客户端指定可见部门、公告 ID 集合或相似度 SQL。
- 同步幂等、单文档事务、版本隔离、可重复执行，是比“调用 embedding API”更值得讲的工程设计。

官方参考：[Ollama Embed](https://docs.ollama.com/api/embed)、[BGE-M3](https://ollama.com/library/bge-m3)、[PGVector](https://github.com/pgvector/pgvector)。
