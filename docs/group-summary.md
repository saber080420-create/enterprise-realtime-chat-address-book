# 群聊摘要与行动项 v1

## 功能与范围

AI 助手新增「群聊摘要」：选择当前加入的群和北京时间范围，展示摘要要点、行动项和可点击原消息引用。负责人/截止时间保存引用原文，不推算“周五”等相对日期，缺失时为 null，页面显示“未明确”。不会创建任务、分配负责人或通知他人。

- 范围为 `[开始,结束)`，最多 7 天；只取时间范围内最新 100 条符合权限条件的文本消息，总计最多 16000 字符。单条超过 2000 字符跳过，超额显示范围受限；附件不解析。群选择列表最多 100 个。
- 原项目使用每成员一份消息副本。查询必须匹配 receiver_id=当前用户，不能收集整个群的所有副本；还需当前 active 账号、合法角色、当前群成员关系、消息时间不早于当前 join_time。系统管理员不自动获得群访问权限。
- 排除撤回、私聊、附件和入群前消息；离群后原文接口也不可访问。不修改已读状态或聊天记录。
- 给模型前、返回结果前都复查群成员身份、消息内容/版本/发送者/时间。撤回、删除、编辑或权限变化会拒绝展示本次结果。最后复查与发送之间仍有竞态窗口，不承诺跨请求强一致，也不能撤回已经发送给 DeepSeek 的资料。
- 模型只接收服务端查询结果，不接收客户端提供的消息正文作为证据。资料被标为低信任数据，提示词要求忽略资料中的指令，但这不是完全防注入保证。

## 输出约束

复用现有模型流式传输、ready/cancel 协议、每用户单请求与单实例 4 路并发、120 秒总超时。摘要不向前端逐段展示原始 JSON，而在服务器缓冲（最多 24000 字符）后校验，再发送 `summary` 事件及 `done`。

当前通过提示词约束 JSON 格式，再做服务端严格校验；没有宣称调用供应商 JSON Schema 强约束或 JSON mode。

- 顶层仅允许 points/actions，两数组各最多 8 项。
- 摘要项只允许 text/evidenceIds；行动项只允许 task/owner/deadline/evidenceIds。
- 每条内容最多 600 字符；负责人/期限最多 100 字符或 null。
- 引用必须非空、唯一且只指向本次实际纳入的消息 ID（使用字符串避免浏览器长整数精度问题）。
- 非空负责人和期限必须在该行动项引用消息中出现连续原文；否则整次失败。此检查不能证明模型对归属、否定、建议或决定的语义理解正确，所以结果仍需人工核对。
- 拒绝未知字段、重复 JSON key、尾随 JSON、Markdown 代码围栏、错误字段类型和不完整生成。无自动修复/重试，避免额外计费；用户可缩小范围重试。
- 无有效消息时不调用模型，Token 0。历史回答不会成为后续摘要证据；结果只在页面内存中，不落库。

## 验收

无需新表或额外 API Key。在原后端终端重启，刷新页面即可进入群聊摘要。当前尚未完成真实 DeepSeek 群摘要的浏览器验收。

使用专用演示群和不含敏感信息的合成对话，例如：

1. “这次只讨论演示项目发布。”
2. “小王请在周五提交测试报告。”
3. “部署时间还没确定，先不要发布。”

生成后核对：报告行动项引用第 2 条，负责人原文“小王”、期限原文“周五”；部署不得被描述为已确定执行。点击引用核对当前原文；空时间范围应 Token 0。再验证撤回、退出群聊和其他账号不能读消息（这些变更涉及群成员或聊天数据，需在演示环境明确授权后进行）。

本轮没有创建演示群、发送真实群消息或将现有聊天送给 DeepSeek。
